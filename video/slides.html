The False Sense of Security

  • Verification proves implementation satisfies the given contract
  • Does not ensure the contract is adequate
  • Vacuous proofs → green tick, zero guarantees
  • No feedback on what the proof actually used

"Verified" ≠ well-specified.
The developer sees a tick and moves on.

Dafny says: ✓ Verified

method DemoImpossiblePrecondition(a: int) returns (r: int) requires forall t :: t*t + 1 <= t*t ensures 2 == 3 { var k := a + 1; var m := k * 2; r := m - k; }

✓ No errors. All proof obligations discharged.

ProofPulse reveals: Vacuous Proof

method DemoImpossiblePrecondition(a: int) returns (r: int) requires forall t :: t*t + 1 <= t*t // CovComplete (!) ensures 2 == 3 // CovTest () { var k := a + 1; // Uncovered var m := k * 2; // Uncovered r := m - k; // Uncovered }

Precondition is unsatisfiable → ex falso quodlibet.
No code contributes. The postcondition is "proved" from nothing.

2 / 5

Three-Valued Proof Coverage

Refining Tomb & Joshi's binary model into graded proof relevance:

CovComplete Contributes to proving a postcondition (spec intent)
CovTest Postconditions unused by callees, or preconditions used in callers but not needed to prove postcondition
Uncovered No proof obligation depends on it
method DemoAbs(x: int) returns (y: int) ensures x >= 0 ==> x == y // CovTest: no caller depends on it ensures x < 0 ==> x + y == 0 // CovTest: no caller depends on it { if x == 0 { y := 0; // Uncovered: redundant for proof } if x < 0 { y := -x; // CovComplete } else { y := IdDemo(x); // CovComplete } }
